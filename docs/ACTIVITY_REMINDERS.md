# 活动助手与提醒中心

入口：网站右上角「提醒」，以及「我的」中的提醒中心。未开启设备系统通知也可以读取自己的站内提醒。

## 提醒范围

- 新活动开放：保留原来的首次开放通知，普通编辑、重新开放不会重复群发。
- 我的报名：正式报名、候补、候补转正、取消、参加时间调整。多场地按对应报名时段逐一比较，转正只通知本人。
- 活动安排：场地名称、球馆地址、起止时间变更或活动取消，只通知关联报名球友和创建者；取消不会在后续无关操作时重复发。
- 分组安排：发布一轮比赛时，只通知该轮实际上场的账号。待发送时若轮次取消或本人被移出，取消该条推送。
- 费用确认：正式分摊生成后，通知所有有分摊金额记录且启用的成员，包括确认者本人。消息含确认版本，点击直达费用页。代报名朋友没有账号时，提醒发给代报名的人，并单独写明朋友的名字。已有正式结果可由创建者或管理员点「提醒未付款」：只提醒还没标记已付款的人（代报名朋友的提醒同样发给代报名的人），每次提醒都会送达，同一版本 6 小时内最多一次。确认通知本身每个版本每个账号仍只发一次，兼容旧提醒记录。重新确认新版本会再通知；尚未发送的旧版本推送取消。系统通知不展示具体金额，打开活动费用页才能看到。
- 赛后评选：活动设置为结束且评选确实开放时，提醒具备投票资格的球友。到达结束时间自动结束不写入数据，也没有定时服务，因此不额外推送；打开活动即可看到已结束和评选开放。
- 临近开场：访问提醒中心时按本人对应场地的正式报名到达时间检查，开场前一小时显示站内提示，候补和已取消报名排除。没有配置脱离访问的定时服务，关闭网站后的准点开场推送不作保证。

## 历史与偏好

最近30天，最多显示40条，可切换全部/未读、逐条打开或全部已读。提醒跳到活动的接龙概览、分组、费用或玩法标签；使用现有手机返回历史。每个账号可选择各类系统推送，临近开场的选项控制站内提示。偏好只作用于本人，站内历史仍保留；取消设备系统通知不会清空站内历史。

原设备订阅和 VAPID 密钥保持不变，不自动申请系统通知权限。不支持系统通知的浏览器依然可以查看提醒中心。系统、浏览器和推送服务仍可能延迟通知。

## 数据与验证

0010 迁移新增 reminder_inbox / reminder_settings，以及 push_jobs.message。提醒和推送收件人快照与活动变更在同一 D1 事务中提交，失败或重复 requestId 不产生虚假提醒。已退出设备、停用档案、过期消息、过时的报名状态和关闭的偏好在发送时重检。私有订阅、其他人的提醒与账号清单不进入提醒 API 响应；所有写入仍有会话、来源、字段校验和速率限制。

验证包含真实 SQLite 事务、伪造账号与已读越权、偏好关闭/重新开启、实际加密个人通知解密、多场地转正、变更收件人、未确认费用不发送、临近开场边界与手机返回。集成测试使用虚构密钥并拦截网络，不向真实球友发送验收消息。
