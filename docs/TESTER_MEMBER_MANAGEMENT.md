# 测试员管理成员账号和临时来宾

测试员是群主在"账号权限"里设置的普通成员（`simulationTester`），原本可以用模拟排场，并为自己创建的活动开启积分赛。现在测试员还可以做"成员账号管理"和"临时来宾管理"。身份仍是普通成员，群组管理页的其他功能都不开放。

谁算有这项权限，统一由 `canManageMembers`（`lib/domain/member-managers.ts`）判断：管理员，或测试员。

## 入口

测试员在"我的"里会看到"成员与来宾管理"按钮，打开的页面只有"成员账号管理"和"临时来宾管理"两块（`app/club-app.tsx`）。管理员仍然看到完整的"管理员设置"。

## 成员账号管理

测试员可以：

- 创建账号：新球友档案、接管没有账号的成员档案，或把临时来宾转为正式成员（[FRIEND_TO_MEMBER.md](FRIEND_TO_MEMBER.md)）。新账号一律是普通成员。
- 为普通成员开通登录、重置密码。

测试员不可以（`canManageAccount`、`assertAccountManageable`）：

- 动群主、管理员或其他测试员的账号：这些账号在列表里显示"由管理员管理"，服务端返回 403。这样测试员无法通过重置密码接管权限比普通成员高的账号。
- 修改名字、修改登录账号、调整账号权限：和以前一样，只有群主可以。

测试员收到全部账号的列表（用来显示每个人的状态，并判断哪些档案已有账号），但不含邮箱；登录账号名只收到自己能管理的账号和自己的（`app/api/club/route.ts`）。普通成员和以前一样，收不到账号列表。审计里的重置密码记录写明"测试员重置登录密码"。

## 临时来宾管理

测试员可以合并重复的朋友、修改朋友信息、把朋友移出或恢复到名单（`guestFriendMerge`、`guestFriendEdit`、`guestFriendHide`）。

"同一场活动里重复的接龙"也可以由测试员取消：服务端只在这是一条真正的重复接龙时，才把测试员当作这场活动的组织者来处理这次取消（`duplicateGuestSignup`，`lib/domain/guest-names.ts`）。重复接龙指同一场活动里、同一宽松昵称（不分大小写、空格和末尾数字）的有效临时来宾接龙，按接龙顺序第一条保留，其余算重复。普通的、只接龙一次的朋友，测试员仍然不能替别人取消。

## 验证

`tests/member-managers.test.ts` 覆盖谁能管理哪些账号，以及重复接龙的判断。`tests/tester-member-management-api.mjs` 走真实的账号接口、俱乐部接口和事务存储，覆盖以下几点：

- 测试员看到的账号列表和登录账号名。
- 测试员能创建普通成员、能重置普通成员的密码；不能重置群主、管理员、其他测试员的密码，也不能为管理员账号开通登录。
- 普通成员什么账号都管不了。
- 测试员能合并、修改、移出朋友；能取消重复接龙，但不能取消第一条或非重复的接龙。
- 测试员不能调整账号权限。
