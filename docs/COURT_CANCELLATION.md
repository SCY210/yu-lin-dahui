# 取消活动内的单个场地

活动创建者、群主和管理员可在场地卡片的「设置」旁点「取消场地」，在确认框里核对影响后执行。比赛报名页的场地列表也有同一个入口。普通成员、非创建者的测试员没有此管理权限。

取消会同时撤销该预约的正式和候补接龙，清除取消申请。球友在其他场地的接龙保留；当其本活动全部接龙已取消时，记录组织者取消的时间、账号及原因。没有独立选场的旧接龙在仍有其他重叠预约时保留。比赛的整场参赛报名保留。

对应预约从可用场地和费用预览中移除，不再计算这片场地的费用。原预约、原接龙、撤下的对局及重排轮次 ID 保存在 `bookingCancel` 审计中。已确认的分摊版本和付款记录保留，管理者须重新确认变化后的费用；取消操作不伪造退款或付款记录。取消最后一片场地后活动仍保留，可重新添加预约并接龙。

场地已有开打、比分或参加记录时，不能用此操作抹去历史。所影响球友仍在其他片场比赛时也暂不执行，先完成该局。这里依据实际记录判断，不以活动的开始时间作为取消门槛。

未开打对局会撤下且不计缺席、败场或扣分。失去参加资格的球友也从其他未开打对局撤下，剩余预排按原有重排规则处理，不重排仍有效的手工阵容、草稿及已开打轮次。赛事对阵保留，尚未开打对局的场地分配解除，之后可在剩余预约上重新开赛。

服务端通过存储中的 `bookingId` 查找活动并验证管理权限，传入其他 `eventId` 不会授予权限。领域变更以克隆状态完成后一次替换，接口沿用原 revision 原子事务和 requestId 幂等保护；并发接龙或编辑使旧确认请求返回 409。没有新增数据库表或生产数据迁移。

验证包括 `tests/booking-cancel.test.ts`、`tests/booking-cancel-api.mjs` 和 `tests/compact-sections-ui.mjs`。
