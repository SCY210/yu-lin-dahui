# 道缘

每对正式球友之间都有道缘，逻辑位于 lib/domain/bonds.ts，阶段与缘值在 lib/domain/bond-tiers.ts。缘值决定当前阶段：

| 阶段 | 起始缘值 |
| --- | --- |
| 萍水相逢 | 0 |
| 泛泛之交 | 300 |
| 金兰之契 | 1,500 |
| 朝夕相处 | 5,000 |
| 风雨同舟 | 15,000 |
| 情同手足 | 50,000 |
| 心有灵犀 | 80,000 |
| 生死与共 | 150,000 |
| 珠联璧合 | 250,000 |
| 情比金坚 | 350,000 |
| 莫逆之交 | 500,000 |

阶段采用各自颜色，最后两阶使用渐变；它们本身不额外发放奖励。

## 缘值来源

- 一起搭档：已完成比赛中同队的小局每局加 60，赢球再加 40。对手关系和单打不增加。每局乘以双方当时阶段的倍率（1、1、2、4、8、10、14、18、22、26、30）。每周搭档约三局、胜率约一半时，一个月内可到第二阶，约半年到第五阶，约三年到最高阶；tests/bonds.test.ts 验证此节奏。历史比赛也计入。
- 不支持直接赠送羽币，避免把多人的羽币汇集到同一账号。旧版短暂开放时产生的 gift_sent / gift_received 转币记录保留，每羽币仍计 50 缘值。
- 赠送商店礼品：宝阁里所有商品都可以送人，包括传音喇叭。treasureRedeem 的 giftTo 指定接收人，message 保存留言。付款者用自己的羽币兑换，即时道缘礼物和送出的传音喇叭每羽币价值增加双方 1 缘值（喇叭按所选时长的价格计），实物及普通虚拟商品沿用每羽币 50 缘值；均不受阶段倍率影响。实物和普通虚拟商品由群主发放；专门的 gift 道缘礼物即时送达，订单直接完成。取消待处理礼品订单会退款，同时去除对应缘值。

送礼沿用羽币账本：送出方的 redeem 记录保存接收人，接收方的 gift_received 记录保存赠送人。收礼记录不转入羽币；双方分别计算得到相同缘值，无需新建表。

## 展示与权限

- 球友档案：app/bond-card.tsx 显示本人和对方的阶段、缘值、进度、搭档倍率、搭档记录、赠礼价值与送礼按钮。位于个人资料和球拍之后；本人档案及临时来宾不展示。
- 我的道缘榜：app/bond-board.tsx 位于最近比赛后，先显示缘值最高的三位，再展开其余。群主和管理员还可查看全群道缘，按成员选择后查看其全部关系，支持搜索；赠礼记录页显示最新 200 条赠礼（giftHistory / bonds.gifts），包含双方、物品或旧版羽币、价值、留言、时间及退款取消状态。
- 成员目录：app/player-directory.tsx 显示与当前查看者的道缘阶段，支持按道缘排序。
- 收礼提示：app/gift-popup.tsx 展示赠送人、礼物和留言。确认后写入 Account.giftSeen；超过 30 天的礼物不再弹出。弹出时先播放一次全屏庆贺特效（见下文）。
- 储物戒：羽林宝阁页的储物戒（app/storage-ring.tsx）列出本人收到的礼物和自己兑换的商品，详见下文。
- 商店账本和订单：显示送出及收到的礼物、订单接收人。

普通成员只收到自己的 bonds.rows 与 me.giftNotices。只有群主和管理员收到 bonds.pairs 及 bonds.gifts，普通成员不能查看其他两人的完整关系或送礼明细。已可见双打对局的同队等级是下述展示例外。全群与个人关系使用相同的历史重算规则。

## 商店即时赠礼

商品详情可选收礼人、数量及最多 60 字留言；购买前再次确认收礼人、总价及增加的缘值。gift 商品必须送给另一个已启用的正式成员；physical 和原有 digital 商品仍可自己兑换，并保留群主发放流程。即时礼物直接成为 fulfilled 订单，不能走待处理订单的取消退款流程。

只有群主可管理商品与库存。服务端检查真实发送者、接收人、价格、库存和余额，扣款、零羽币收礼记录、订单及库存由同一个事务保存。重复请求不会重复扣款或增加道缘。新增流程不增加表、定时任务或轮询请求。

初始正式站目录是群主配置，不由迁移自动覆盖：清风传意 10 羽币 / 10 缘值，同心玉佩 30 / 30，金兰灵契 80 / 80。已有商品保留，名称、价格、库存和上下架状态可继续编辑。这些虚拟礼物表达心意并增加道缘，不承诺头像、称号或实物奖励。

## 赠礼成长节奏

即时礼物三档兑换效率相同（每羽币 1 缘值），没有大额购买加成。仅靠新即时礼物从零达到最高阶段 500,000 缘值，需要消费 500,000 羽币；搭档比赛仍按原有阶段倍率成长。每次赠礼把总缘值 giftAffinity 固化到订单和双方账本，后续调价或规则修改不重算已购礼物。缺少快照的旧记录继续按原有每羽币 50 缘值解释。客户端提交 expectedAffinity，服务端对照当前商品计算；旧页面或不一致的确认被拒绝并要求刷新，不先扣款。

## 储物戒

储物戒存放成员已有的道具，由服务端 storageRing（lib/domain/treasure-shop.ts）按订单计算，随 treasureShop.ring 下发，不新增表、轮询或定时任务。

- 收录：别人送给自己的礼物（任何类型），以及自己兑换给自己的商品；自己送出去的礼物不在自己的储物戒里。被取消退款的订单移出储物戒。最新的在前，最多 300 件。
- 状态：道缘礼物显示「珍藏中」；实物和普通虚拟商品显示「待宗主发放」或「已发放」；传音喇叭显示「待使用」「传音中」「已用完」或「已被撤下」。待使用的喇叭排在最前，并有「使用」按钮。
- 只返回商品名、类型、数量、状态、时间、赠送人、留言和喇叭信息，不含账号标识；商品名和喇叭内容同样按屏蔽词遮盖。

### 送传音喇叭

- 在喇叭详情或球友档案的送礼表单里选一档时长和收礼人，送礼人不写喇叭内容。服务端要求数量为 1，按所选时长的价格扣币、减 1 个库存，订单直接完成，但不带内容和结束时间，因此不会出现在顶部横幅里。
- 收礼人在储物戒里点「使用」，写最多 50 个字，确认后发出 treasureHornUse：只有收礼人本人可以使用，从使用时刻起按所买时长上横幅，横幅上显示收礼人的名字（订单的 hornStart 记录使用时间）。重复同一请求不会重复生效；用过的喇叭不能改写。写入审计日志。
- 收礼提示里，喇叭礼物写着「已收进储物戒，去羽林宝阁使用」。

## 全屏收礼特效

app/gift-celebration.tsx 在收礼弹窗出现时，用 portal 在整个页面上方播放一次约 4.6 秒的庆贺：金光闪现、旋转光芒、五簇烟花、飘落的花瓣与金叶，中间放大展示第一件礼物的图标，并写着「天降仙缘」和「某某 赠你……」。同一批礼物只播放一次；结束后完全隐藏。

特效不接收点击（pointer-events: none），不挡住弹窗按钮，不自动确认、不发请求、不播放声音；只用 transform 和 opacity 动画。沿用共享可见性观察器，在后台暂停；系统设置为减少动态效果时整个特效不显示，弹窗照常出现。

## 礼物图标与收礼动效

app/gift-art.tsx 绘制共享的内联 SVG：清风传意为灵羽流风，同心玉佩为双环玉佩，金兰灵契为金纹卷轴。商店卡片、详情、订单和收礼列表使用同套图标。按名称识别，并识别收礼记录的数量后缀；自定义或改名的礼物使用通用礼盒，不猜测其他商品的图标。

收礼弹窗以本批第一条礼物展示一次灵气汇聚动画，约 3.2 秒后静止，其余礼物在列表中展示。普通轮询不重播，同一批确认后仍走原有 giftSeen 逻辑。动画不自动确认、不发请求、不改羽币或缘值、不播放声音。沿用共享可见性观察器，在离屏及后台暂停；prefers-reduced-motion 显示静态完成态。小屏弹窗允许纵向滚动，始终可直接关闭或收下礼物，不必等待动画结束。

## 对局搭档徽章

app/team-bond.tsx 为 11 个等级提供独立纹样与矿物色徽章：初叶、双芽、双环、明月、风雨同舟、同心结、灵犀星、双剑、双翼、宝钻、莲华星阵。双打同队的两个已启用正式球友，在每队球友姓名上方以紧凑单行显示当前道缘徽章和阶段；桌面附带 Lv.1–Lv.11，手机双场窄列收起数字等级，完整等级保留在悬浮提示及无障碍说明中；尚无缘值仍显示第一阶。单打、临时来宾、无效或重复名单、取消对局不展示。只有进行中且活动未结束的高等级徽章播放轻微呼吸与灵纹环绕，预排和历史结果使用静态图。所有动效在后台或离屏暂停，减少动态效果时完全静止。

服务端 matchBondTiers 只为本次响应中可见活动的实际同队组合返回 players 与 tier。不返回精确缘值、赠礼记录、收支或其他组合；活动局部读取也不附带其他活动占场信息对应的徽章。原有 bonds.rows / pairs / gifts 权限不变。关系重放与等级索引按版本缓存，不为每个对局重扫历史，也不增加轮询或计时任务。换人后客户端核对双方 player ID，旧组合的徽章立即隐藏，直到新响应到达。新赠礼、取消赠礼及赛果等版本更新使等级刷新。

实时排场、预排和模拟对局共用 MatchCard；模拟使用自身的隔离历史计算道缘，不改真实记录。历史对局显示的是这对球友的当前道缘，不是比赛当天的冻结等级。徽章不影响分组、胜负、积分、修为或一比一礼物规则。
