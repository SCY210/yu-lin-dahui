# 操作日志

宗门事务中的操作日志可查看请求时刻向前滚动 7 天（168 小时）的记录，包含恰好位于起点的记录，不显示未来时间的记录。按操作时间从新到旧排列，同一毫秒内按日志标识倒序排列。原有操作人、动作、原因和可展开的变更详情继续显示。

展开日志面板时通过 `GET /api/audits` 读取首批 50 条，点击「加载更早日志」继续翻页，直到最近一周的可见记录全部读完；不再把可查看范围限制在最新 50 条。点击「刷新日志」重新读取当前最近一周，关闭面板会取消尚未完成的请求。

接口逐次验证登录身份和管理员权限，并在实际读取的快照中重新确认权限。沿用 `privateEventState` 对已删除活动、宝阁记录的可见性限制，以及原有屏蔽词处理。普通成员和测试员不可通过接口访问管理员日志，响应使用 `Cache-Control: no-store`。退出、切换账号和失去管理员权限时不继续展示错误账号的接口结果。

翻页游标使用最后一条记录的时间和标识，固定首次请求的结束时间，避免期间新写入的记录扰乱翻页。服务端始终按当前时刻限制最近 7 天，不能伪造游标查询更早的日志；时间范围过期后需要刷新。客户端追加时去重，并移除已超出本次返回时间范围的记录。

一周日志只在展开、手动刷新或翻页时按需读取；普通俱乐部轮询仍保持原有最多 50 条的响应，活动范围响应仍不带日志。新增读取复用增量快照，不运行维护、不生成日志、不改业务状态；不增加轮询、时钟驱动维护或条件读取边界，也不修改历史数据保留策略。授权的完整导出仍按原有规则保留可导出的完整历史。

验证：`tests/audit-log.test.ts` 覆盖七天边界、超过 50 条、同毫秒分页、快照、非法游标及隐私；`tests/audit-log-api.mjs` 覆盖接口鉴权、权限变化、翻页和失败保护；`tests/audit-log-ui.mjs` 覆盖操作人、超过 50 条的展示、刷新、普通轮询不重复请求、权限变化、空态和关闭取消。
