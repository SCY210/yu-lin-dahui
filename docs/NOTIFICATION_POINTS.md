# Phone notification enrollment points

Policy `2026-10-13-v1` awards the initial 10 doubles season points once per account after explicit enrollment and push-service acceptance. A member with an existing subscription can claim from notification settings after reading the same rules. Legacy clients and silent status checks do not enroll an account in this policy.

Only phone notifications participate in points. Computer notifications remain available but enabling, disabling or reporting permission loss on a computer never awards or deducts points and never settles a phone closure. After the initial award, explicitly disabling any registered phone device deducts 30 doubles season points. Returning to the site also deducts 30 when the browser reports denied/default on a known enabled device. These paths share one pending closure per account and do not stack deductions while that closure is unresolved. Explicitly re-enabling through the website and passing push-service verification now awards only 10 points, never a 30-point refund. Each reactivation references its closure audit ID (reactivates), can be awarded once, and allows a subsequent closure to deduct another 30. Repeated enrollment while already enabled awards nothing. Awards, penalties and new reactivation bonuses belong to the month they occur; the original penalty remains in its original month. For example, initial enable +10, close -30, re-enable +10 totals -10. Singles points, match counts, wins, cultivation and grouping strength are unchanged.

The notification prompt and settings disclose awards, penalties and reactivation bonuses before enrollment; disabling requires confirmation. Notifications remain optional. Device-specific logout, provider expiry, delivery errors and subscription cleanup do not deduct points. Browser/system permission loss is checked on entry without asking for permission automatically. A missing subscription alone is not evidence of permission loss. Some operating-system switches do not affect browser-visible permission and cannot be detected. Disabling notification categories does not remove a device subscription.

Server authentication determines the account. Device writes and immutable audit deltas share an optimistic club-revision transaction, with retry on conflicts. Device ownership is checked again within the penalty transaction. Device eligibility is classified on the server from the request User-Agent and mobile client hint; it is not accepted as a client JSON flag. iPhone and Android Mobile qualify; desktop, tablet and unknown classifications do not. This is conservative browser-reported classification, not spoof-proof hardware attestation. Receipts persist phone eligibility and the penalty transaction rechecks that eligibility. Existing unclassified receipts start ineligible and are upgraded only by a successful granted-permission status check or enrollment on a recognized phone. Historical settled scores are preserved. An opaque 256-bit device token in a Secure/HttpOnly/SameSite=Lax cookie (up to one year) is matched against a server-side SHA-256 receipt bound to the account and subscription; raw tokens are never returned in JSON or stored in the audit ledger. A new browser without a receipt or an existing owned subscription is not penalized. Existing enabled browsers obtain a receipt during the normal granted-permission status check. Logout and provider cleanup deactivate the receipt. The server trusts an authenticated browser permission report; it does not have OS attestation. Enrollment validates subscription keys and requires successful push-service acceptance before the first reward and each reactivation reward; this is not proof that the operating system displayed the notification. Provider failure grants no points. Existing historical awards, penalties and already-settled 30-point refunds remain immutable and recognized by the ledger. New code never creates a refund entry.

The penalty is a product rule requested by the owner, not a legal compliance guarantee. Where personal-data processing relies on consent, a penalty for withdrawing consent can undermine freely given consent; disclosure alone does not resolve that issue.

Tests use synthetic members, in-memory SQLite and a mocked push provider. Never test incentive accounting against production members.
