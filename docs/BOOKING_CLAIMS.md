# 约场时段认领

创建活动时不必知道每片场地是谁约的：约场人默认是**待认领**，由实际预约并垫付场费的球友在活动页认领自己约的时间。组织者已经知道是谁约的，也可以在创建时直接选，或者先登记自己，之后再由实际约场人认领替换。

## 时间线

活动接龙页每片场地下方直接显示「约场认领」时间线（`app/booking-claims.tsx`），不折叠。赛事活动的比赛场地也显示同样的时间线。

- 时间线按场地预约时间从开始到结束画成一条，每一段的长度和时长成正比，段内写着时间和约场人。
- 颜色表示认领状态：橙色斜纹是**待认领**（还没人认领），主题色是**组织者登记**（组织者填了约场人，但本人还没认领），绿色是**已认领**（约场的球友自己认领，或组织者纠正过的认领）。时间线下方有颜色说明。
- 标题右侧写着还有几小时待认领；没有待认领时显示"已全部登记"，全部由本人认领时显示"已全部认领"。
- 时间线下方是「认领我约的时间」按钮；组织者还有「纠正约场人」按钮。点按钮弹出窗口，按马德里时间选开始和结束时间。认领窗口默认从第一段待认领的时间开始，长两小时。
- 时间线显示时，场地卡片顶部不再重复"约场 …"一行；只读、已取消或已删除的活动不显示时间线，仍显示这一行。

## 成员认领

- 启用账号的球友可直接认领自己实际预约的时间，无需组织者批准；不要求本人在这片场地报名，因为也可能替群里约场而不参加。
- 时间必须在该场地预约内，以半小时为步长，认领至少一小时，拆分后的约场段也至少一小时。整个预约本来不足一小时的，可以整段认领。每人两小时仅是常见预约方式，不作为网站硬性限制。
- 待认领的场地可以一段一段认领：认领中间两小时后，前后没人认领的时间仍是待认领，不会自动算到任何人头上。没有约场人的时段用不带 `advancedBy` 的交接记录表示（`lib/domain/booking-advancers.ts`）。
- 认领只更新对应范围的约场人和场费垫付归属。沿用原来的 `advancedBy`、`handovers`，不会拆出新场地，不改变接龙人数、场费总额、分摊比例、比赛或预约起止时间。
- `Booking.claims` 保存已认领区间、球友和时间。待认领的时间和组织者登记的约场人都可以被实际约场人认领；已经被其他球友认领的区间不能覆盖。自己的相邻时间可以继续认领。
- 接口从存储账号确定本人，不信任提交的角色、组织者身份或其他活动 ID。携带打开表单时的场地和认领快照；场地、价格或认领被改后返回 409，刷新后重新选择。标准请求 ID、修订号及原子保存同时防止并发覆盖和重复提交。

## 组织者纠正与费用

- 活动创建者、群主和管理员可点「纠正约场人」，选中时间和实际约场成员，包括已经被认领的区间。成员不能代认领或借其他活动的创建者身份纠正。
- 原有场地设置、费用页更正仍有效。场地设置里可以把某一段改回待认领，这一段的认领记录随之去掉。修改已认领区间的约场人时同步认领归属；缩短预约时裁掉范围外的认领，延长时不把新增时间自动认领给原球友。
- 已删除、已取消的活动禁止认领；草稿只允许组织者操作。费用尚未确认时允许补认领，即使活动已经结束。
- 场地还有待认领的时间时，不能确认费用分摊，提示先认领或由组织者填写约场人（见[费用垫付](FEE_ADVANCES.md)）。
- 一旦存在已确认费用版本，认领入口关闭。组织者使用原费用页的垫付人更正，并重新确认分摊；原确认版本和付款标记不被认领操作改写。
- 认领及纠正写入审计，包含真实操作者、时间范围和修改前后场地。这里只记录预约与垫付归属，不会实际转账。
