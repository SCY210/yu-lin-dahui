# Personal score entry on app return

Opening the authenticated app or returning it to the foreground offers score entry for the account's own started, still-playing games. The dialog asks whether the game is finished; physical completion is not inferred from a timer. The member can enter the actual result or postpone it. A compact persistent banner provides a manual route back to the pending list.

Eligibility uses the existing, authorized club projection and existing `canRecordScore` policy. The current account's enabled player must appear on one team, with a started non-future match, its playing parent round and a visible non-deleted activity. Draft/cancelled activities, finished/voided games and unrelated/proxy games are excluded. Administrator access to another player's game does not make it that administrator's personal reminder. Activity ending does not silently discard an otherwise recordable pending result. The newest pending game is offered first; older pending games can be selected.

The initial visit is consumed even if there are no pending games. Ordinary polling and automatic live assignments therefore never continually reopen score entry. A return to the foreground refreshes shared state before arming another visit. Existing forms, dialogs, pending writes and connection errors defer the prompt. A score draft already open is preserved on foreground return. Closing/postponing consumes that visit; manual access remains available. Account changes remount the reminder and stale asynchronous responses cannot arm it for another account. If someone else records or voids a selected game, it disappears from the pending UI.

Score submission uses the original dialog and original optimistic, idempotent API, so the existing server permission, revision, score validation and live-court progression still apply. No completion is stored without the user confirming actual scores. Unrecorded games now start with blank score fields, clearing an input keeps it blank, and adding optional extra games never inserts invented 21:15 results. Existing recorded results remain available when correcting history. New completions use the server's completion time; historical corrections retain the original exact timestamp without truncating seconds. Mobile score fields request a numeric keyboard and identify the member's team.

No schema migration, background phone notification or new scoring permission is introduced. The banner is separate from the existing activity notification center.

Tests cover personal participation, proxy/admin separation, permissions, activity/round visibility, future and completed records, ordering, one prompt per visit, empty initial visits, blocking/postponement, foreground response races and safe blank score drafts. A headless React test exercises the actual reminder and form: deferred initial popup, postpone/manual return, blank numeric inputs, empty-submit rejection, clearing/editing values, successful completion, no immediate next-game popup and foreground return. Dialog shells substitute for browser portals; real device layout was not verified because the desktop browser tool could not initialize. The fixture is under tests, never a published route. The original scoring and live-play handler tests remain part of regression validation.
