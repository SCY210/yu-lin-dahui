# 段位分、修仙境界与赛季积分

网站只有两个分数：

- **段位分**（长期分，FIDE 式 Elo）：反映球友真实水平，决定修仙境界。自动分组用同一公式只回放双打小局，单打不改变分组实力。不随季度、年度重置，只有连续 3 个月没有计分小局才回到 1000 分重新定级。实现见 `lib/domain/realm-rating.ts`。
- **赛季积分**：只用于季度 / 年度排名。每个计分小局赢 3 分、输 1 分，赢段位分更高的对手另有加成。实现见 `lib/domain/season-points.ts`、`lib/domain/ranking.ts`。

原先只增不减的累计成长规则（赢 10、输 3、当天首局奖励、每日上限）已停用；原先单独的隐藏分组实力分改为段位分的同一公式（见“分组实力”和“迁移”）。

## 段位分公式

- 每人从 1000 分起。每个已完成的计分小局单独结算；三局两胜按实际打完的每一局分别计算。
- 预期胜率 `E = 1 / (1 + 10^((对方分 − 本方分) / 400))`，本局变化 `K × (结果 − E)`，赢 1、输 0；四舍五入为整数（正负对称，`roundDelta`）。
- K：每人前 20 个计分小局 K = 32（新手期），之后 K = 16；搭档各按自己的计分小局数取 K。
- 双打按队伍平均计算（群主看过模拟后的选择，`realmPolicy.doubles = 'team'`）：本队两人平均分对比对方两人平均分得到预期胜率，四个人的段位分都通过两队平均分进入计算，同队两人加减相同；搭档各用自己的 K，所以仍在新手期的一方变化约加倍。例：A 队 1200 + 900（平均 1050）对 B 队 1050 + 1050（平均 1050），四人都已过新手期：A 赢，A 两人各 +8、B 两人各 −8；A 输，A 两人各 −8、B 两人各 +8。若换成 1300 + 900（平均 1100），A 赢各 +7、输各 −9。
- 代码仍保留 `'individual'`（每人用自己的分对比对方平均分）仅作对照，上例在该模式下为 +5 / +11 与 −11 / −5；它在均衡分组下会把所有人压回 1000 附近，因此没有采用。
- 单打是同一公式的一对一情形，单打与双打共用一个段位分。

| 分差 | 强方赢 | 弱方爆冷赢 |
| --- | --- | --- |
| 0 | ±8 | ±8 |
| 50 | +7 / −7 | +9 / −9 |
| 100 | +6 / −6 | +10 / −10 |
| 150 | +5 / −5 | +11 / −11 |
| 200 | +4 / −4 | +12 / −12 |
| 300 | +2 / −2 | +14 / −14 |
| 400 | +1 / −1 | +15 / −15 |

（K = 16；新手期 K = 32 约翻倍。双打的“分差”是两队平均分之差。功能说明里的表格由 `exchangeRow` 按同一公式生成。）

## 哪些小局计分

`isRatedMatch`：已完成、`monthly` 与 `elo` 都为真、没有已应用的让分、双方都有人且没有同一人、至少一个有效小局、完赛时间不晚于当前时间。所以友谊赛、已应用让分、取消、弃权、进行中和未来完赛的记录既不改变段位分，也不产生赛季积分。重复的比赛编号只计一次；含有已删除球友档案的比赛跳过。

回放顺序完全由历史决定：整场结束时间 → 比赛编号 → 小局顺序；每局的变化都按该局之前的分数同时计算。纠错、作废、补录后从头回放。

## 长期不打才重置

- 段位分是长期分，季度、年度都不重置。
- 连续 3 个日历月（`realmPolicy.inactivityMonths`）没有计分小局，从最后一个计分小局的结束时间算起：段位分回到 1000，计分小局数、胜负清零，重新定级（前 10 局显示“定级中”）并重新进入新手期（前 20 局 K = 32）。
- 判断在回放里进行（`inactiveAt`）：回来后的第一个比赛开始时，若距上次已满 3 个月，先重置再结算这一局，该局记为 `reset`；读取时若到当前时间已满 3 个月，也显示为重置后的状态。3 个月内回来打球则一直保留原分数。
- 重置只影响段位分和境界；历史比赛、档案统计和赛季积分都保留。

## 境界

| 境界 | 段位分 |
| --- | --- |
| 炼气 | 849 及以下 |
| 筑基 | 850–999 |
| 金丹 | 1000–1149 |
| 元婴 | 1150–1299 |
| 化神 | 1300 及以上 |

- 每个境界 150 分（`realmPolicy.band`）。达到门槛立即晋升；降级有 30 分缓冲（`realmPolicy.demotionBuffer`）：已持有的境界只有跌破“门槛 − 30”才失去（元婴低于 1120 才降为金丹）。从更高境界跌落时，落到仍在其缓冲内的最高境界（`settleRealmIndex`）。
- 缓冲按活动判断：一次活动全部结算后检查一次（回放中以活动的最后一个计分比赛为检查点），活动中途短暂跌破缓冲、结束时回到缓冲内不降级。
- 每个境界分为初期（0–33%）、中期（34–66%）、后期（67–99%）；炼气按 700–849 计算进度，700 以下为 0%。化神 1300–1449 同样分三期，1450 分及以上显示“化神圆满”（100%）。
- 定级：已结算的计分小局少于 10 局（`realmPolicy.placementGames`）时，球友在任何页面都看不到境界、阶段和境界进度条，只看到中性的“定级中 · N/10 局”标签和段位分；段位分照常加减，定级期间不使用缓冲。第 10 局结算后直接显示当时段位分对应的境界，此后才按缓冲规则升降。
- 只计已结算的小局：进行中活动的小局不计入 N，显示为“另有 N 小局待活动结束后结算”；活动结束后一起计入。
- 隐藏的原因：所有人从 1000 起，定级期几乎人人显示金丹，徽章没有意义。
- 数据：`realmLedger` / `realmSnapshot` 和排行榜、`playerStats` 等领域结果仍保留完整境界（回放、迁移审计和测试使用）。`projectClubState` 在发给页面时用 `visibleRealm` 把定级中的境界去掉。

### 为什么是每境 150 分、缓冲 30 分

用合成球会模拟（16 名虚构球友，真实水平 N(1000, 150)，每周一次、每人约 8 局，均衡分组，40 个随机种子，两年）比较几种区间：

| 方案 | 每人每季境界变动 | 4 周内又变回 | 两年后 炼气/筑基/金丹/元婴/化神 |
| --- | --- | --- | --- |
| 每境 100 分，缓冲 15（旧） | 0.99 次 | 36% | 29 / 20 / 20 / 13 / 18 % |
| 100 分，缓冲 30 | 0.71 次 | 21% | 27 / 21 / 19 / 14 / 19 % |
| 100 分，K = 12 | 0.71 次 | 31% | 26 / 23 / 22 / 16 / 14 % |
| 125 分，缓冲 25 | 0.69 次 | 26% | 22 / 26 / 24 / 16 / 12 % |
| **150 分，缓冲 30（采用）** | **0.56 次** | **22%** | **19 / 29 / 26 / 17 / 8 %** |
| 200 分，缓冲 30 | 0.44 次 | 22% | 13 / 35 / 33 / 17 / 2 % |

旧区间平均每人每季变一次境界，三分之一多在 4 周内又变回去，化神比元婴还多。150 分 / 缓冲 30 让变动减半、来回跳从 36% 降到 22%，分布中间多两头少，化神约 8%。200 分时化神几乎无人能到。模拟假设的水平差距是否符合真实球会，应在有一两个月真实数据后复查。

## 活动结束后结算

沿用 `settledMatchFilter` / `activityConcluded`：活动到点结束、提前标记结束或取消后，其比赛才计入可见段位分、境界和定级局数；找不到活动记录的旧比赛完赛即计。活动进行中，本场已完成的小局显示“另有 N 小局待活动结束后结算（暂计 ±X 分）”，暂计值 = 包含进行中活动的完整回放分数 − 已结算分数。

## 赛季积分与排行榜

- 每个计分小局：输 1 分、赢 3 分；赢下的一方若赛前本队平均段位分比对方低 50–149 分另加 1 分，低 150 分及以上另加 2 分（`seasonPointsPolicy`）。单打按两人各自的段位分比较。比较使用该局开打前的实时段位分（含进行中活动已打完的小局），与段位分回放同一次计算。
- 季度 / 年度双打榜积分 = 该周期每个双打计分小局的赛季积分之和 + 群主手动积分调整；单打榜 = 单打小局的赛季积分之和，不含手动调整。年度积分等于四个季度之和。每个周期从 0 开始累计，只有群主扣分可能让积分为负。
- 赛季积分与段位分互不影响：积分奖励多打和赢球，段位分只看对手强弱下的胜负。榜单行里另给出 `upsetPoints`（本周期强弱加成合计）和 `matchPoints`（比赛积分合计）。
- 按马德里开赛月份归属，同分依次比较计分小局胜率、局均净胜，仍相同并列；正式账号的启用球友入榜，代报名朋友不入榜。
- 榜单保持即时：录入比分后，进行中活动的小局立即计入，并在行内标注“含进行中 +X”；境界和段位分在活动结束后才结算。
- 计分局数、胜负、胜率、净胜只统计计分小局；让分局、友谊赛只计入“实际比赛”局数。
- 不再提供月榜：页面只有季度榜和年度榜（双打 / 单打）。领域层的单月 `leaderboard` 只留给群主的“历史赛季规则重算”预览。
- 各月赛季规则里的 `win` / `loss` / `cap` 不参与积分，`k` 也不再使用；目标分、领先分、封顶分（比分校验）仍然有效。历史周期按现行规则从现有比赛记录重新计算。

## 分组实力

`replayRating` 用段位分的同一公式（每局结算、队伍平均、新手期 K、3 个月重置）只回放 2 对 2 双打小局，把实时结果（包括进行中活动已完成的小局）写入 `player.rating` / `ratedGames`，`ratingChanges` 为每局每人一条（`id = 比赛编号:小局序号:球友`，`algorithm = 'realm-elo-v2'`）。自动分组、固定搭档、实时排场、师徒 / 大腿身份和让分建议都读这个值；单打不会改变它（群主的决定），只打双打的球友它与段位分完全相同。管理员设置的 `initialRating` 和赛季 `rules.k` 不再影响任何分数（字段保留可读）。

比赛卡片上的队伍标签（`teamRealmLabel`）按两队已结算的平均段位分显示境界名，队里有人还在定级中时显示“定级中”。

## 迁移

- `enableEloRealms`（elo-v1）：首次读取时写入 `settings.realmVersion = 'elo-v1'` 并追加审计。段位分每次读取时由比赛记录派生，所有人从 1000 起回算。
- `mergeStrengthRating`（realm-elo-v2）：由 `lib/club-maintenance.ts` 在首次读取时运行一次，用段位分回放重写所有球友的 `rating` / `ratedGames` 和 `ratingChanges`，写入 `settings.strengthVersion = 'realm-elo-v2'`，并追加 `mergeStrengthRating` 审计（每位球友合并前后的实力）。已有版本标记时不再执行，重复加载不增加修订号。之后每次录分、纠错、作废都会再次回放。
- 赛季积分、境界门槛和 3 个月重置不需要迁移：每次读取都从比赛记录重新计算，上线后历史季度和年度榜按新规则显示。

## 模拟验证（段位分公式，合成球会）

16 名虚构球友，真实水平 N(1000, 150)，每周一次、每人约 8 局，均衡分组，30 个随机种子，直接调用 `realm-rating.ts`（旧的 100 分区间下的结果，用来比较双打计算方式）：

| 方案 | 全员平均漂移（52 / 104 周） | 与真实水平秩相关（104 周） |
| --- | --- | --- |
| 队伍平均（已采用） | +0.36 / +0.36 | 0.94 |
| 队伍平均，加入 6 名中途新人 | +1.25 / +1.25 | 0.95 |
| 队伍平均，一半对局随机分组 | −1.00 / −1.00 | 0.94 |
| 个人计算（对照，未采用） | +0.65 / +0.69 | 0.52 |

- 不通胀：队伍平均方式下双方 K 相同时每局严格零和（只有一方含新手期球友时才不为零，98.8% 的小局合计为 0）；全群平均只在开头定级期偏移，之后保持不变，因此不需要额外的零和修正。
- 对照：按个人计算时，强者总被分组搭配较弱的搭档，队伍胜率约 50%，但个人预期胜率按自己的高分计算，所以长期被拉回对手平均分附近，几乎没人进入高境界，且与真实水平的相关性随时间下降。
