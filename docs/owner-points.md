# 群主手动调整积分

入口：我的 → 群组管理 → 手动调整积分。选择启用的球友、加积分或扣积分、计入月份、1–1000 的整数分数，填写原因后保存。

仅持久化群主身份可执行 `grantPoints`，普通管理员与成员不可使用。服务器忽略客户端 actor、isOwner、id 等字段。此命令沿用 `/api/club` 的认证、来源与请求体校验、限流、必需版本检查、请求 ID 幂等和 D1 原子提交。

积分调整作为结构化、不可编辑的 `audits` 记录持久化（action 为 `grantPoints`，changes 为 playerId、period、points、reason）。同一条记录同时构成调整账本与操作审计，不需要新表或重写已有数据。月份采用 2000–2100 年范围；比赛规则重算不改动调整记录。

榜单总分 = 1000（`periodPointsBase`，每个周期的起算分）+ 有效计分赛的段位分变化 + 指定月份的手动积分调整；行内 `pointsChange` 为去掉起算分后的有符号部分，`manualPoints` 为调整合计。加分、扣分都直接叠加在起算分之上，例如本季度没打计分赛、被扣 30 分显示 970 分；多次大额扣分仍可能低于 0，由群主自行把握。季度、年度榜累加其月份内的记录；不改比赛、出场数、胜率、段位分、境界或 Elo。排行榜显示最终积分，不显示“含群主加分”等附注。调整记录入口仅群主可见，已有管理员操作日志与导出权限保持原规则。

验证：`tests/point-grants.test.ts` 覆盖权限、输入校验、周期汇总、段位分隔离、扣分后的积分变化和投影（断言 `pointsChange`）；`tests/ranking-periods.test.ts` 验证调整叠加在 1000 起算分之上；`tests/point-grants-api.mjs` 使用内存 SQLite 与真实 API/store 验证持久化、重复请求、并发版本冲突和回滚，不接触生产资料。

加分提交正数，扣分提交负数；`grantPoints` 为兼容旧客户端和已有账本保留命令名。服务端允许 −1000 至 +1000 的非零整数，普通管理员和成员不能加减分。旧加分记录完整保留，扣分追加新记录；数据库重载、历史规则重算均不会清除调整。
